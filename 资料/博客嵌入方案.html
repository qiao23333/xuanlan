iframe 的一个坑，提前说
Safari 的 ITP 和 Chrome 逐步收紧的第三方存储策略下，iframe 里的 localStorage 可能被隔离或清空， 也就是「历史记录 / 复盘」在嵌入状态下可能存不住。算法本身不受影响（纯内存计算）， 只是不落盘。所以我建议卡片上保留「新窗口打开」的入口。

方案 C · 用 Cloudflare 绑个自己的域名（可选）

嫌 github.io 域名不够自己的，可以绑个子域。玄览是纯静态站，绑域名很简单：

位置做什么
GitHub PagesSettings → Pages → Custom domain 填 xuanlan.你的域名.com
Cloudflare DNS加一条 CNAME：xuanlan → qiao23333.github.io，Proxy 状态先关（DNS only）
验证 HTTPS 后再把 Proxy 打开（橙色云），SSL/TLS 模式设为 Full（不要 Flexible，会重定向循环）
仓库里GitHub 会自动写入 CNAME 文件；下次我 push 时记得别覆盖它

怎么保证博客里永远是最新版

不用做任何事。.github/workflows/pages.yml 会在每次 push 到 master 时自动跑： 类型检查 → 内核 49 个测试 → 前端 51 个测试 → 构建 → 部署。测试不过就不发布， 所以博客上的链接永远指向「通过全部测试的最新版」，不存在链接失效或版本落后的问题。

顺带一提：玄览的分享功能生成的 #/r= 链接，会把生辰与起卦种子编码进 URL， 别人打开能逐字重现同一份结果。写博客时如果想展示某个具体案例， 直接贴分享链接比截图更有说服力 —— 读者点进去能自己翻、自己验。
