## 玄览 项目性能优化（继续上次）

### 1. 紫微斗数计算降载（ziwei adapter）
- 问题：`calculateAll` 全量 30.5s，紫微占 99.7%（23.7s）。旧 adapter 调用 `calculateZiweiChart` 全 7 个 scope，每个跑 `buildAnalysisPayloadV1`（~5s），且 `payloadByScope`/`horoscope`/`decadalTimeline` 全局无人消费，前端只用 `astrolabe.palaces`。
- 改法：`packages/core/src/adapters/ziwei.ts` 改用公开子路径 `mingyu-core/ziwei/iztro` 的 `buildZiweiChartInput` + `buildAstrolabeFromInput`，只算本命盘。
- 效果：紫微 23724ms → 45ms；全量 30556ms → 148ms（206×）。数据体积 1610KB → 9KB。
- 正确性：6 个样本（含早子时空宫、闰月）盘面逐字段一致，已写回归测试 `packages/core/test/ziwei.test.ts`（golden 校验命宫主星/地支/十二宫）。

### 2. 内核懒加载（首屏瘦身）
- 问题：内核（iztro+mingyu-core+历法库）~1.6MB 在首屏被静态拉入。
- 改法：
  - 新增 `src/loadCore.ts`：带缓存的动态 `import('./core')`。
  - `src/App.tsx` / `src/history.ts` 改为运行时 `await loadCore()`。
  - `packages/core/src/registry.ts` 不再 import adapters（SYSTEM_META 零依赖内联）。
  - `src/core-meta.ts` 抽出 `AXIS_LABELS`/`overallAgreement`（纯展示常量），`ConsensusDashboard.tsx` 改引它，切断 App→ConsensusDashboard→core 静态边。
  - **关键坑**：`vite.config.ts` 的 `manualChunks` 把 Vite 的 `__vitePreload` 助手塞进 vendor-iztro，反而让入口静态导入整个内核——已删除 manualChunks，改由 Vite 自动按动态 import 切分。
- 效果：首屏入口 `index-*.js` 200KB（gzip 70KB）+ CSS 33KB，HTML 仅引一个脚本、零预载内核；1.24MB 内核随「开始推演」按需下载。
